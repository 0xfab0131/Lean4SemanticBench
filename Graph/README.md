# L4SB — Lean 宣言依存エクスプローラ

`lake exe decl_report MyProject > report.jsonl` の出力を読み込んで、
宣言の入出力・最小の仮定・依存構造を辿るための単体アプリ。

## 任意のプロジェクトを解析する

解析は同梱の `Commands/Scripts/l4sb.sh` で行う。対象プロジェクトの内側に
衛星ワークスペースを生成し、**対象と同一の toolchain・同一の依存実体**で
`decl_report` をビルド・実行する(環境同一性)。使い方と設計は
`Commands/Scripts/README.md` を参照。

```
Commands/Scripts/l4sb.sh all /path/to/Project ModuleName
```

**解析対象は先にビルドしておく。** `decl_report` が読むのは olean であって
ソースではない。ソースを編集した直後に走らせると、古い環境を解析した結果が出る。
`l4sb.sh report` はこのビルドを自動で行う。

## この Graph/ 自身の位置づけ

この lakefile は `LeanDeclReport` を**開発・単体ビルド**するためのもの
(IDE の補完、コンパイル確認、対話コマンドの試用)。依存は importGraph のみで
mathlib には依存しない。リビジョンは lean-toolchain と同名の公式タグに固定し、
`lake-manifest.json` は `lake update` が生成するロックとしてコミットする
(手で編集しない。意図は lakefile、記録は manifest)。

```
cd Graph
lake build decl_report      # ライブラリと実行ファイルをビルド
```

## 使い方

`index.html` をブラウザで開くだけ。ビルド不要。
CDN から Tailwind CSS と p5.js を読むのでオンラインである必要がある。

```
index.html        アプリシェル
index.js          配線とキーボード操作
js/graph.js       グラフ算法（純関数）
js/store.js       状態と派生計算
js/canvas.js      p5 による円錐グラフの描画
js/panels.js      DOM 側のパネル
js/persist.js     読み込んだレポートとピンの保持
js/sample.js      動作確認用サンプル
```

データの読み込み順は **前回の保持 → 既定の監査結果 → サンプル**。
一度読んだものは IndexedDB に保持され、次に開いたとき自動で戻る。
「データ」ボタンからは、既定の監査結果とサンプルをいつでも選び直せる。

既定の監査結果は `report.jsonl` を JS に埋め込んだもの。`index.html` は `file://`
で開く前提なので、隣の `report.jsonl` を `fetch` すると opaque origin として
拒否される。そのため次を一度実行して埋め込む（生成物は `.gitignore` 済み）。

```
node Graph/make_default_report.js          # Graph/report.jsonl を埋め込む
```

算法層だけは Node で検査できる。

```
node Graph/ldr_check.js                    # Graph/report.jsonl を対象にする
node Graph/ldr_check.js path/to/other.jsonl
```

## 二つの円錐と四種類の辺

中心 $d$ のまわりに二つの錐を置く。MacNeille の極（polarity）と同じ形で、
上が下界作用素の側 $\downarrow d$、下が上界作用素の側 $\uparrow d$ に対応する。
極小元を押したときに出る経路は順序区間 $[t,d] = \uparrow t \cap \downarrow d$ である。

| 位置 | 錐 | 内容 |
|---|---|---|
| 上 | 依存 $\downarrow d$ | $d$ が使う宣言。$d$ を証明するのに何が要ったか |
| 下 | 参照 $\uparrow d$ | $d$ を使う宣言。$d$ から何が出たか |

それぞれの錐は二種類の辺を含み、色・線種・矢じりの三つで区別する。

| 錐 | 辺 | 意味 |
|---|---|---|
| 上 | ━ 藍 実線・塗り矢 | **型依存** — $d$ の主張に現れる。何を述べているかを決める |
| 上 | ╌ 紫 点線・開き矢 | **値依存** — $d$ の証明にだけ現れる。カーネル検査済みなので刈り込める |
| 下 | ━ 青緑 実線・塗り矢 | **主張で参照** — $d$ を主張に含む宣言。すなわち $d$ についての定理・性質 |
| 下 | ╌ 橙 点線・開き矢 | **証明で参照** — $d$ を道具としてのみ使う宣言。$d$ について何かを述べてはいない |

下の二つが交わらないのは Lean 側の性質による。`directDepsOfCore` は型にも値にも
現れる定数を型依存側にのみ入れるので、$\mathrm{refType}(d)$ と $\mathrm{refValue}(d)$ は
排他的に分割され、和がちょうど「$d$ を使う宣言」全体になる。

当初これを左右二つの錐に割ったが、下半分を半々にすると両方とも狭くて読めなかった。
上錐が型依存と値依存を線種で描き分けているのと同じ流儀に揃え、一つの錐を下半分
いっぱいに開いている。`下錐` の切替（`v`）で **両方 / 主張のみ / 呼出のみ** を選ぶ。
既定は両方なので、呼び出し元は最初から下に開いている。

## 導出図と法則の在庫表

右パネルには二つの見え方がある。

**導出図。** 証明項に現れる定数を並べても証明の図にはならない。役割で分ける。

| 役割 | 判定 | 扱い |
|---|---|---|
| 公理 | `kind = axiom` | 決して畳まない |
| 補題 | `isProp` が真 | 導出図の前提。横線の上に並ぶ |
| 語彙 | `isProp` が偽 | 主張を書く道具。線の外 |
| 骨組み | `And.intro` / `PSigma.mk` / 再帰子など | 畳んで件数だけ |

前提を横線の上、規則名を線の右、結論を下に置く。前提を開くとその場で
自分の推論図に育つので、入れ子がそのまま導出の入れ子になる。
グラフ側でも骨組みを**縮約**する。$\mathrm{adj}'(u)$ を「骨組みを通り抜けた先の
最初の非骨組み」と定めた商で、到達可能性を保ったまま辺を張り替える。
表示専用で、$\min(\downarrow d)$ や $\lvert\downarrow d\rvert$ は常に元のグラフで測る。
監査の結果を歪めてはならない。

**法則の在庫表。** 行が関係・演算、列が反射 / 非反射 / 対称 / 推移 / 反対称 /
全域 / 単調 / 可換 / 結合 / 冪等 / 吸収 / 分配。Lean 側が仮定と結論の形から
判定した `shape` と、担い手 `shapeRel`（吸収・分配は相方 `shapeRel2` も）を
集計する。右端に、列の組から読める判断を出す：

$$\text{反射}+\text{推移} \Rightarrow \text{前順序}
\;\xrightarrow{+\text{反対称}}\; \text{半順序}
\;\xrightarrow{+\text{全域}}\; \text{全順序}，\qquad
\text{可換}+\text{結合}+\text{冪等} \Rightarrow \text{半束}
\;\xrightarrow{\text{相方も半束}+\text{吸収}^{\leftrightarrow}}\; \text{束}
\;\xrightarrow{+\text{分配}}\; \text{分配束}$$

各判定は主張を **（枠, 担い手, 法則）** へ写すチャージであり、外側の枠を
検査してから担い手を確定する。反対称律は枠が `Eq` / `Iff` で担い手が仮定側、
全域性は枠が `∨`。枠を見ないと「全域性を可換と誤認する」type の取り違えが
起きる（実測して修正済み）。吸収・分配は二演算法則なので担い手が対になる。

**空欄は「まだ証明されていない」であって「成り立たない」ではない。**
判定は誤って付けない向きに倒してあるので、別の言い回しで証明されているものは
取り逃す。同じ原則から **`sorry` を含む宣言は在庫に数えない**
（空欄は正直でよいが、埋まった欄が嘘をつくことは許されない）。

## 球面モード

一つの扇を全ての部分グラフで共有すると、どれも狭くなって重なる。平面モードで
部分グラフを帯で囲っても、占有できる角度は増えない。**球面モード（`b`）は共有をやめ、
部分グラフごとに扇をまるごと与える。**

各部分グラフには重さ（可視ノード数）に比例した経度の区間を割り当てる。正面に来た
区画だけが読める大きさで描かれ、脇へ回った区画は水平に圧縮されて薄くなる。
中心は経度に依らず原点に固定するので、層を行き来しても現在地を失わない。

右上の地球儀が区画の配置と大きさ、いまどこを向いているかを示す。内側の環が上錐
（依存）、外側が下錐（参照）。掴んで回すか、押した位置へ最短回りで正面が移る。
`Shift`+ホイール、`[` `]` でも回る。

自己解析の実測（中心 `buildReport`・深さ 2 の依存錐 493 ノード・11 区画）で、
ノードの平均表示幅は **135 px → 158 px**。
区画をまたぐ辺は張らない。経度が違うものを結んでも読めないため。
分割の商品質は **clopen 欠損**（元グラフでの区画間依存辺の本数。0 なら各区画が
「外と依存し合わない部分理論」）で測り、`ldr_check.js` が情報として出力する。

## 操作

| | |
|---|---|
| 単クリック | 選択（詳細に表示。中心は動かない。履歴も動かない） |
| ダブルクリック | 中心を移動（上をたどれば登り、下をたどれば降りる） |
| ホイール | 拡大縮小（カーソル位置を固定） |
| ドラッグ | 移動 |
| ノード外側の `+k` | その枝だけを展開 |
| 極小元のチップ | そこへ至る経路だけを表示（経路は自動で展開される） |
| マウスの戻る／進むボタン | 履歴を登る / 降りる |
| `Ctrl+Z` / `Ctrl+Y` | 同上（`Backspace`、`Alt+←→` も同じ） |
| `/` `t` `m` `v` `p` `0` `+` `-` `Esc` | 検索 / 型のみ / 粒度 / 下錐 / ピン / 全体 / 拡大 / 縮小 / 解除 |

移動ボタンはキャンバスの内側、左下に置いてある。探索中に視線が乗っている場所と
ボタンの場所が離れていると、あるのに気づかない。左右のパネルは境目を掴んで
幅を変えられる（ダブルクリックで既定値に戻る）。幅は次回にも引き継がれる。

詳細欄の `📘 docs` と `🔎 LeanSearch` は、その宣言を
[mathlib4 の公式ドキュメント](https://leanprover-community.github.io/mathlib4_docs/)
と [LeanSearch](https://leansearch.net/) で引く。Mathlib 由来の宣言は
この画面には型と依存しか無いので、定義そのものを読みたくなったときの出口になる。

左の一覧は四通りに並べ替えられる。**実装順**（レポートの行順＝ファイル内で宣言された順）、
**依存少**（直接依存の少ない順＝原始的なものから）、**名前空間**（namespace ごとに束ね、
名前空間は初出順）、**ツリー**（モジュールのディレクトリ構造）。

右下の**探索履歴**は木である。中心を移動したときだけ記録し、覗くだけの単クリックでは
記録しない。戻ってから別の枝に入っても元の枝は残る。直近 50 手を保持し、
超えると古い根の側から忘れる。

**ピン留め**は中心・展開状態・深さ・錐の表示・経路表示・倍率をまとめて保存する。
クリップボードへのコピーと JSON ファイルへの保存ができ、書き出した JSON は
ドロップで読み戻せる。

## 設計上の判断

**アプリシェルを viewport 高に固定した。** 旧版はドキュメントがスクロールする前提だったので、
キャンバス上でホイールを奪うとページが動かせなくなり、奪わないとズームできなかった。
シェルを固定して内部だけスクロールさせれば、この衝突自体が消える。

**単クリックとダブルクリックの意味を分けた。** 旧版は単クリックで中心が飛ぶので、
少し見たいだけでも現在地を失い、探索が萎縮した。

**色は全てリテラルで持つ。** 旧版はホストの CSS 変数（`var(--surface-1)` など）に
依存していた。SVG は `fill` に解決不能な値を渡すと属性を無視して既定の黒にするため、
変数を提供しない環境ではノードが黒い塊になった。

**グラフとリストを併置した。** グラフが得意なのは大域的な形で、
内容の閲覧と監査（どれが未完成か）はリストの方が圧倒的に速い。両者は補完関係にある。

**直交格子をやめて極座標にした。** 層を横一列に並べると、扇入り・扇出しの大きい
宣言のところで辺が束になって重なり、どれがどこへ行くのか読めなくなる。中心から
放射する構造は本来「中心の上のファイバー束」なので、その形のまま置く。角度方向が
底空間、半径方向が導出の深さである。三つの錐に交わらない角度区間を与えたので、
**別の錐に属する辺は原理的に一本も交差しない**。

**半径を密度から決めた。** 層の半径は「その層の全ノードが弧上で重ならない最小値」と
「一枚一枚を最大幅で置ける理想値」の両方から決まる。層が薄いときは後者が効くので、
数個しかない層が中心の近くで潰れて点になることがない。層が厚いときは理想値の頭打ちで
止まり、代わりにノードが細くなる。

層の間隔 $\Delta r$ には導出済みの下限がある。同角 $\theta$ の隣接リング間で
$\Delta x \approx \Delta r|\cos\theta|,\ \Delta y \approx \Delta r|\sin\theta|$ であり、
軸平行矩形の非重複には最悪角($\tan\theta = h/w$)で
$\Delta r \ge \sqrt{w_{\max}^2 + h^2} \approx 189$ が必要になる。
旧値 136 はこれを下回り扇の水平寄りで重なり得た(自己解析で実測して 200 に修正)。
現在は全ての深さで矩形の重なりが 0 であることを `ldr_check.js` が確認している。

**層を跨ぐ辺を膨らませた。** 層が一つおきに繋がる辺をまっすぐ引くと、間の層の
ノードを突き抜けて、どこから来た線なのか読めなくなる。跨ぐ段数に応じて角度方向へ
逃がす。膨らむ向きは辺の名前から決めるので、フレームごとに揺れない。

**単クリックで履歴を動かさない。** 比較のために隣を覗くだけで現在地を失うのでは、
探索が萎縮する。移動は明示（ダブルクリック）に限り、そのときだけ履歴に積む。

## 算法

層化は最長路レベリング。

$$\ell(d) = 0, \qquad \ell(v) = \max\{\ell(u)+1 : u \to v\}$$

非巡回性から well-defined で、$(u,v) \in E \Rightarrow \ell(v) > \ell(u)$ なので
全ての辺が厳密に外向きになる。最短路（BFS）ではこれが成り立たず、
層をまたぐ辺が描画から漏れる。$\ell(v)$ は「$d$ から $v$ への最長導出鎖の長さ」を意味し、
極小元が必ず最外層に出る。

層 $\ell$ を半径 $r(\ell)$ の円弧に載せ、角度は親の角度の重心で並べる（交差削減）。
半径は

$$r(\ell) = \max\left(r(\ell-1) + \Delta r,\ \frac{|L_\ell| \cdot s_{\min}}{\theta_1 - \theta_0}\right)$$

で、$s_{\min}$ は 1 ノードが占める最小の弧長。辺は極座標のベジエで、中間半径
$\tfrac{r_u + r_v}{2}$ まで半径方向に出てから角度方向へ移る。同じ扇に属する辺が
自然に束ねられる。

既定の中心は、極大元（他のどの宣言からも使われない＝そのライブラリの最終結果）のうち
導出鎖 $\mathrm{depth}(n) = 1 + \max\{\mathrm{depth}(m) : n \to m\}$ が最長のもの。
DAG 上の一回の走査で全ノード分が得られるので、宣言数に対して線形。

経路の抽出は順序区間。$d$ から $t$ への経路上にあるノードの集合は

$$[t, d] = \uparrow\! t \cap \downarrow\! d$$

に一致する。極小元を押すとこの区間だけを表示するので、
「この定理はどこで選択公理を使うのか」に正確に答えられる。

$\min(\downarrow d)$ は宣言 $d$ の性質なので、いま何を展開しているかとは無関係に
完全な下方閉集合から計算する。可視集合から計算すると初期表示で空になり意味も変わる。

層内の順序は重心法で4回掃引して交差を減らす。
表示名は集合内で一意になる最短接尾辞（`Nat.add_comm` と `Int.add_comm` を区別する）。

型依存と値依存を分けている。定理の証明項に現れる依存はカーネル検査済み
（証明無関係性）なので、主張の構造を見たいときは「型のみ」で刈り込める。
定義の実装に現れる依存は意味論的に本質的なので残る。
